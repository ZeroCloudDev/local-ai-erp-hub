# ERRATA — Local AI ERP Hub, as is

This file is the state of the project at the end of season 1 (EP01–EP05): what works, what breaks, what you have to build yourself, and what is not known. Every number comes from `benchmarks/results/` and was measured **2026-10-23 to 2026-10-26**. Models and Ollama change; re-run the benchmark before you trust any of these numbers on your own machine.

## How it was measured

- **Documents:** 71 per pass. 11 are the test files from the series (EP01 messages, EP02 PDF invoices, EP03 receipt photo, EP05 documents). 60 are synthetic messages in the same style, generated by `benchmarks/make_synthetic_set.py` (seed 20261023) together with the expected outcome, before any model saw them.
- **Same job for every model:** the series pipeline and validation, plus one check that exists only in the benchmark: every item must be in the price list, at that price.
- **Machines, CPU only, no graphics card:**
  - ThinkPad P16s Gen 2, Ryzen 7 PRO 7840U, Ollama 0.40.5, 3 passes per document.
  - HP ProBook 470 G0 (2013), i7-3632QM, 16 GB, no AVX2, Ollama 0.40.7, 1 pass, 4 models.
- **Rules written before the first run** (`benchmarks/README.md`, 2026-10-23): any silent error → `OUT`. `RECOMMENDED` needs at least 90 % correct outcomes and a permissive license (Apache or MIT). Speed decides nothing.
- **Silent error** = wrong data approved with nothing stopping it. Everything else is either correct or goes to quarantine for a person.

## What works

- **granite4:3b** passes every rule: 0 silent errors, 90.1 % correct, 2.5 GB, about 9.5 s per document on the P16s. **ministral-3:8b** also passes (92.5 %), but is more than twice as slow and needs 6.8 GB.
- The **price-list check** caught every wrong price and every unknown product code in the test, for every model.
- Overnight estimate for granite4:3b (8 h ÷ measured s/document, **not** an 8-hour run): about 3,000 documents on the P16s, about 820 on the ProBook.

## What breaks

1. **qwen3:4b dropped a line.** `syn_hard_noqty_06`: the message has a module line and a battery line ($199.99 each, quantity not written). The model returned only the first line, in 3 of 3 passes. The message has no total, so validation had nothing to compare (`results/qwen3_noqty06_raw_check_probook_2026-10-25.txt`).
2. **qwen2.5:3b, the model the series was built on, approved a row without a unit price.** `syn_easy_01`: quantity and line total were right, unit price empty. Same mistake on both machines.
3. **Temperature 0 is not deterministic.** gemma4:e2b changed its outcome on 7 documents between passes.
4. **Two items in one sentence** is the hardest case for every model. granite4:3b got it right 3 times out of 21 (the rest go to quarantine, so it is safe, but it is work for a person).
5. **Bigger is not better, and the label is not the measurement.** qwen2.5:7b was far weaker than qwen2.5:3b. gemma4:e4b needed 10.6 GB and was the weakest. gemma4:e2b ("effective 2B") needed 6.4 GB.
6. **Swapped items with the same price** are not caught by the validation.
7. **The EP01 JSON "lock" was looser than the video said.** In `core/schemas.py` the `items` list is optional (`default_factory=list`), so a model may leave it out.

## What you have to build yourself

- **Your own expected outcomes.** Without them you can measure speed, but you cannot count silent errors.
- **Your own price list and rules.** The catalog check exists only in the benchmark. The EP01 validation does not check the product code; the EP05 database step does reject a missing code (`INVALID_SKU`), but only for EP05 documents.
- **A rule for messages without a total.** A first draft is in `core/completeness.py` (`--completeness-check`). Its measurement run (2026-10-25) did not finish, so it is **not measured** and not recommended.
- **Someone who owns the quarantine** every morning. With granite4:3b that is about 1 in 6 correct documents.
- **Re-run the selection** whenever you add a model or change the schema.

### Schema experiment (2026-10-26, P16s, 1 pass, `--schema strict`)

Making `items` required (at least one line) helped two models and hurt three:

| Model | Correct before → after |
|---|---|
| gemma4:e4b | 43.7 % → 81.7 % |
| qwen2.5:7b | 53.5 % → 81.7 % |
| granite4:3b | 90.1 % → 78.9 % |

| phi4-mini | 57.7 % → 52.1 % |
| gemma4:e2b | 77.5 % → 74.6 % (within run-to-run noise) |

No new silent errors. The new quarantines are items without a product code. "Before" is pass 1 of the night runs. Source: `shootout_p16s_2026-10-26_083749_*.csv`.

## What is not known

- All test messages are synthetic, in English, in one style. **Real customer messages have not been tested.** Format for your own: `benchmarks/real_messages_FORMAT.md`.
- Raspberry Pi 5: not tested yet.
